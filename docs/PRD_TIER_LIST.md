이 문서는 개발할 기능의 요구사항이다. 현재 배포된 수동 티어표가 이 기능을 제공한다는 뜻은 아니다.
`티어표 작성 근거` 위키의 기존 연구는 참고 자료이며 개인화 산식을 검증한 자료가 아니다.

## 1. 문제와 목표

같은 챔피언도 이용자의 현재 실력 구간, 숙련도와 선픽 상황에 따라 좋은 선택인지 달라진다.
ABOUTLOL은 하나의 공통 등급에 더해 **나에게 맞는 챔피언의 선택 적합도**를 보여 준다.
이용자는 지표를 살펴보고 주요 지표를 제외했을 때 자신의 티어표가 어떻게 달라지는지 확인할 수 있다.

목표는 다음과 같다.

1. 챔피언의 score를 산출하고 score 구간으로 등급을 구분한다.
2. 현재 티어와 챔피언별 숙련도를 Riot API로 가져와 개인화한다.
3. 개인 입력 없이도 개인 관련 요소를 제외한 일반 티어표를 제공한다.
4. `가중치` 메뉴에서 지표값과 반영 방식·비중·점수의 근거를 설명한다.
5. 주요 지표는 토글로 제외하고 기존 위키를 통해 이의를 제기할 수 있게 한다.
6. 장인 의존도·선픽 적합도·조작 난이도는 운영자가 초기 값을 정하고 이의제기를 검토해 수정한다.

### 1.1 확정된 방향과 후속 결정

| 구분 | 내용 |
| --- | --- |
| 사용자 요청으로 확정 | 개인화 티어표, score 구간별 등급, 복수 가중치, 현재 티어·챔피언 숙련도의 API 자동 입력 우선, 개인 입력이 없으면 일반 결과, 지표 막대그래프, 주요 지표 제외 토글, 운영자 지표 설정, 기존 위키 연계 이의제기 |
| 범위에서 제외 | 최고 티어 수집·활용, 다음 패치 너프 확률 |
| 별도 모델 논의 | score의 범위·단위·산식·변환식·계수·등급 경계, API 숙련도의 점수 반영 방식 |
| 이 문서의 제안 | API로 가져올 수 없는 입력만 선택적으로 직접 입력, 비회원 브라우저 설정 저장, 초기 한국 서버 솔로 랭크, 단계별 출시 |

`0~100`, `90 이상 S`, `80 이상 A`는 처음 설명한 예시다. score 범위나 등급 경계로 고정하지 않는다.
이 PRD에서 정규화 산식이나 평가 모델을 먼저 결정하지 않는다. 모델 논의 결과는 별도 명세로 기록하고 연결한다.

### 1.2 범위

- 탑·정글·미드·원딜·서폿의 챔피언 티어표를 제공한다. 같은 챔피언도 포지션별로 별도 평가한다.
- 초기 비교 대상은 한국 서버 솔로 랭크를 제안한다. 다른 서버·모드는 별도 데이터가 준비된 뒤 추가한다.
- 공식 현재 랭크를 입력으로 이용한다. 이용자의 숨은 MMR·ELO나 예상 랭크를 산출하지 않는다.
- 첫 범위의 개인 정보는 현재 티어와 챔피언별 숙련도다.
- 주요 지표의 제외 토글을 제공한다. 계수 자체를 사용자가 편집하는 슬라이더는 후속 결정이다.

## 2. 용어와 불변식

| 용어 | 의미 |
| --- | --- |
| 지표값 | 챔피언 또는 이용자의 관측·평가 값. 예: 승률 51%, 조작 난이도 9/10 |
| 반영 가중치 | 지표가 score 계산에 미치는 비중. 지표값 9와 비중 9%는 다르다 |
| score | 선택 적합도 모델이 산출하는 점수. 수치 범위와 단위는 별도 모델 명세에서 정한다 |
| 일반 티어표 | 개인 입력과 그 입력에 의존하는 요소를 제외한 기본 티어표 |
| 개인화 티어표 | 현재 티어·챔피언 숙련도 중 이용 가능한 개인 입력을 반영한 티어표 |
| 사용자 설정 티어표 | 일반 또는 개인화 계산에서 주요 지표를 토글로 제외한 결과 |
| 장인 의존도 | 숙련된 이용자에게 성과가 집중되는 정도에 대한 운영 평가. 조작 난이도·개인 숙련도와 구분한다 |
| 산출 불가 | 해당 모델에서 계산에 필요한 유효 입력이 부족한 상태 |

모든 화면에서 다음을 지킨다.

- 개인 입력이 없거나 API가 실패한 것을 낮은 티어·숙련도 0으로 간주하지 않는다.
- 미입력·제외 요소와 그 요소에 의존하는 계산을 적용하지 않는다. 모델별 결측·제외 처리 규칙을 따른다.
- 지표값과 반영 비중, score와 등급을 구분한다.
- 개인 정보·토글은 그 이용자의 결과만 바꾼다. 다른 이용자의 일반 결과나 원본 지표를 변경하지 않는다.
- 근거 없는 챔피언을 F로 보내거나 기존 수동 등급에서 score를 역산하지 않는다.
- 같은 입력과 같은 데이터·모델 버전에는 같은 결과가 나와야 한다.

## 3. score 산출 함수와 별도 모델 명세

### 3.1 입력과 출력

계산은 UI와 분리한 하나의 함수가 담당한다. 아래는 책임을 표현한 계약 초안이다.

```text
calculateChampionScore({
  championSlug, position,
  dataSnapshot, modelVersion,
  personalProfile?, excludedFactors
}) -> {
  score: number | null,
  grade: S | A | B | C | D | E | F | null,
  mode: general | personalized | customized,
  factors: [{ id, rawValue, source, application, explanation, status }],
  omittedFactors, coverage, reasons
}
```

- 입력은 버전이 있는 스냅숏이다. 계산 함수 내부에서 실시간 외부 API를 조회하지 않는다.
- score를 0~100으로 제한하거나 임의로 잘라내지 않는다. 실제 범위·단위는 모델 명세에 따른다.
- 등급 경계는 모델과 함께 버전으로 관리한다. 구간은 서로 겹치지 않고 유효 score를 빠짐없이 분류한다.
- 표시용 반올림은 등급을 바꾸지 않는다. 경계 근처에서는 판단에 필요한 정밀도를 제공한다.
- `coverage`는 입력이 얼마나 준비됐는지 설명한다. 승률이나 추천 정확도라는 뜻으로 표시하지 않는다.
- 요소의 상태는 `적용 / 사용자가 제외 / 개인 입력 없음 / 데이터 부족 / 해당 없음`으로 구분한다.
- 산출 불가일 때 score와 등급은 `null`이며 NaN·Infinity·임의의 0점을 표시하지 않는다.
- 같은 등급에서는 score 내림차순, 완전히 같은 점수에서는 한글 이름순으로 정렬하는 것을 제안한다.

### 3.2 모델 논의에서 정할 사항

다음은 별도 모델 명세의 책임이다. 이번 PRD에서 후보 산식이나 숫자를 확정하지 않는다.

- score의 의미·범위·단위, 등급 경계와 경계 검사.
- 각 지표의 변환식·방향·계수 및 개인 입력과의 상호작용.
- API 숙련도 레벨·포인트·최근 플레이 시각 중 사용할 값과 반영 방식.
- 지표 간 중복 효과, 필수 입력·결측 처리·토글 제외 시 재계산 규칙.
- 점수 근거의 설명 방식. 비선형 모델이면 단순 기여분 합산으로 설명할 수 있는지 함께 정의한다.
- 검증 자료·평가 기준과 모델 버전 게시 절차.

score는 경기 승리 확률이나 이용자의 랭크가 아니라 챔피언 선택 적합도다.

> 2026-10-06: 모델 명세 초안은 [TIER_MODEL.md](./TIER_MODEL.md)다. 공식 패치노트의 버프·너프를 정답 라벨로 쓰는
> 순서형 로지스틱 회귀이며, 학습 자료가 쌓이기 전까지 공개 점수로 쓰지 않는다.

| --- | --- | --- | --- |
| 픽률 | % | 같은 서버·모드·패치·포지션·실력 구간의 집계 | 분모·포지션 판정·표본·집계 범위를 명시한다 |
| 승률 | %, 경기 수 | 같은 범위의 승리 경기 / 유효 경기 | 표본과 불확실성을 함께 표시한다 |
| 밴율 | % | 같은 범위의 밴 경기 비율 | 포지션별 배분 정의가 없으면 전체 밴율로 표시한다 |
| 장인 의존도 | 운영 평가 눈금, 척도는 후속 정의 | 운영자 메뉴에서 직접 설정 | 의미·눈금·근거를 정하고 위키 이의제기를 검토해 수정한다 |
| 선픽 적합도 | 운영 평가 눈금, 척도는 후속 정의 | 운영자 메뉴에서 직접 설정 | 포지션별 평가와 근거를 관리하고 위키 이의제기를 검토해 수정한다 |
| 조작 난이도 | 운영 평가 눈금, 9/10 표시는 예시 | 운영자 메뉴에서 직접 설정 | 공개된 평가 기준에 따라 설정하고 위키 이의제기를 검토해 수정한다 |
| 개인 숙련도 | Riot 숙련도 레벨·포인트 등 원본 단위 | Champion Mastery API 우선 | 조회 성공 시 설문을 대체한다. score 입력으로 변환하는 방식은 모델 논의에서 정한다 |
| 현재 티어 | 현재 랭크·디비전·큐 | League API 우선 | 보드에 맞는 큐를 선택하고, 조회 성공 시 설문을 대체한다 |

### 4.1 데이터의 유효 범위

- 통계에는 서버·모드·포지션·실력 구간·패치·기간·표본·갱신 시각을 붙인다.
- 여러 범위의 통계를 같은 보드에 섞지 않는다. 현재 티어를 사용해 데이터 범위를 선택하는 방식은 모델 명세에 따른다.
- 일반 보드의 기본 실력 구간은 출시 전 결정하고 표시한다. 개인 입력이 없다고 임의 랭크를 부여하지 않는다.
- Data Dragon은 챔피언·스킬·이미지 카탈로그이며 전 서버 승률·픽률·밴율 공급원으로 간주하지 않는다.
- 집계 통계 공급원·수집 규모·갱신 비용은 별도로 결정한다. 현재 개인 전적의 최근 20경기를 전체 통계로 사용하지 않는다.
- 최소 표본·최신성 기준은 출시 전 정한다. 자료가 부족한 신규·개편 챔피언은 산출을 보류할 수 있다.

### 4.2 결측과 비교 가능성

- API 또는 직접 입력으로 개인 정보가 확보되면 그 입력을 반영한다. 설문을 응답하지 않았어도 API 값이 있으면 개인화할 수 있다.
- 개인 입력을 전혀 확보하지 못했거나 일반 모드를 선택하면 개인 관련 요소를 제외한다.
- 현재 티어만 있거나 일부 챔피언의 숙련도만 있으면 이용 가능한 값만 반영하고 부분 적용 상태를 설명한다.
- API 오류와 정상 응답의 빈 결과를 구분한다. 랭크 없음·숙련도 기록 없음의 모델 처리 규칙은 별도 명세에서 정한다.
- 필수 공통 지표가 부족하면 산출 불가다. 선택 지표 결측과 개인 입력 없음은 구분한다.
- 보드는 `일반 / 개인화 / 부분 적용`과 적용 요소·미적용 이유를 설명한다.

## 5. Riot API 개인 입력과 선택적 직접 입력

### 5.1 자동 입력 우선

Riot ID로 계정을 선택하고 PUUID를 확인한 뒤 서버에서 다음 데이터를 조회한다.
한국 서버 기준 개인 데이터는 해당 플랫폼의 API를 사용한다.

| 입력 | 공식 API | 필요한 원본·범위 |
| --- | --- | --- |
| 현재 티어 | `league-v4`: `/lol/league/v4/entries/by-puuid/{encryptedPUUID}` | `queueType`, `tier`, `rank`, 필요 시 `leaguePoints`. 솔로 랭크 보드에는 해당 큐의 현재 랭크를 사용 |
| 챔피언별 숙련도 | `champion-mastery-v4`: `/lol/champion-mastery/v4/champion-masteries/by-puuid/{encryptedPUUID}` | `championId`, `championLevel`, `championPoints`, `lastPlayTime`. 전체 항목을 가져와 카탈로그와 연결 |

- 조회가 성공한 현재 티어·챔피언 숙련도는 직접 입력을 대체한다. 동일 항목을 다시 응답하도록 요구하지 않는다.
- 숙련도 API의 원본 단위를 그대로 보관·설명한다. 레벨·포인트를 임의의 0~10 자가 평가와 동일시하지 않는다.
- 최고 티어는 요청·설문·저장·계산 대상에 넣지 않는다.
- 계정 선택은 데이터 조회 대상의 선택이다. Riot ID 입력만으로 계정 소유권이 인증됐다고 표시하지 않는다.
- API 키·호출은 서버에 두고 캐시·동시 조회·429와 오류를 처리한다. 재조회는 명시적으로 제공하고 갱신 시각을 표시한다.

공식 데이터 구조는 [League API](https://developer.riotgames.com/apis#league-v4/GET_getLeagueEntriesByPUUID)와
[Champion Mastery API](https://developer.riotgames.com/apis#champion-mastery-v4/GET_getAllChampionMasteriesByPUUID)를 따른다.
구현 시 사용할 키와 실제 계정으로 접근·응답을 검증한다. 이번 변경은 API 연동 요구사항의 갱신이다.

### 5.2 API로 가져올 수 없을 때

- 계정 미선택·키 미설정·조회 실패로 확보하지 못한 입력만 선택적으로 직접 입력하도록 제안한다.
- 현재 티어 직접 입력은 공식 랭크·디비전, 언랭크·모름·건너뛰기를 제공한다.
- 챔피언별 숙련도의 직접 입력 척도와 API 값과의 관계는 모델 논의에서 정한다. 모든 챔피언 응답을 강제하지 않는다.
- API 조회 실패는 데이터 없음이나 숙련도 0으로 저장하지 않는다. 재시도·직접 입력·일반 보드 선택을 제공한다.
- API가 다시 성공하면 API 값을 우선 적용하고 출처 변경을 표시한다. 직접 입력과 API 값을 합산해 이중 반영하지 않는다.

### 5.3 흐름과 저장 제안

1. 최초 진입은 일반 티어표다. `나에게 맞추기`에서 Riot ID를 선택한다.
2. 현재 티어·챔피언 숙련도를 자동 조회하고 적용될 데이터와 출처·갱신 시각을 확인한다.
3. 가져오지 못한 입력은 선택적으로 직접 입력하거나 생략한다.
4. `적용`하면 이용 가능한 개인 입력과 토글을 반영해 다시 계산한다.
5. 개인 설정 삭제·직접 입력 수정·API 새로고침·일반 모드 전환을 제공한다.
6. 최초에는 비회원 브라우저 설정 저장을 제안한다. 계정 동기화와 다른 기기 복원은 후속 결정이다.
7. 개인 입력은 URL·공개 위키·분석 이벤트에 자동 첨부하지 않는다. 저장 위치·보존·삭제 방법은 구현 시 정해 개인정보처리방침에 반영한다.
8. 저장 실패 시 해당 방문 동안 적용하고 저장되지 않았다는 사실을 알린다.

## 6. 주요 가중치 제외 토글

- 첫 범위는 주요 요소의 ON/OFF다. 후보는 개인 숙련도·조작 난이도·장인 의존도·선픽 적합도·픽률·밴율이다.
- 토글을 끄면 해당 요소와 그것에 의존하는 계산을 제외한다. 구체적인 재계산은 후속 모델 명세에 따른다.
- 원본 지표값은 바꾸지 않는다. 제외 설정은 이용자의 보드 전체에 적용한다.
- score·등급·정렬·점수 근거 설명이 함께 바뀐다. 스냅숏 로드 이후 220ms 이내 반영을 목표로 한다.
- 제외된 항목과 현재 모드를 표시하고 `기본 설정으로` 한 번에 복원한다.
- 적용할 지표가 없으면 지표 선택 안내를 표시하고 임의의 점수·등급을 만들지 않는다.
- 공개 설정은 URL로 복원한다. 포지션·모드·제외 지표 ID만 담고 Riot ID·개인 데이터는 자동으로 담지 않는다.
- 일반 설정은 동일 스냅숏·모델에서 재현한다. 개인화 결과 복원에는 해당 이용자의 개인 입력이 필요하다.

## 7. 티어표와 `가중치` 메뉴

### 7.1 메뉴와 지면

- 기능 안에 `티어표 / 가중치` 메뉴와 `나에게 맞추기`를 제공한다.
- `티어표 작성 근거`·`티어표 건의` 위키 진입점을 유지한다.
- 포지션 탭과 S~F 행에 아이콘·챔피언명·score를 표시한다. 점수 단위는 모델 명세에 맞게 표시한다.
- 패치·비교 범위·갱신 시각·일반/개인화/부분 적용 상태를 첫 지면에서 확인할 수 있게 한다.
- 챔피언 위키 링크와 점수 근거 열기를 구분하고 산출 불가를 등급 밖에 표시한다.

### 7.2 지표 막대그래프

`가중치`에서 포지션·챔피언을 선택하고 각 지표를 가로 막대로 읽는다.

```text
이렐리아 / 미드
조작 난이도  9 / 10           [근거] [이의제기]
선픽 적합도  운영 평가 미입력  [정의] [이의제기]
개인 숙련도  Riot 조회 결과    [출처] [새로고침]
```

`9/10`은 사용자 설명에 따른 UI 예시이며 실제 이렐리아 값이나 score 범위로 고정하지 않는다.

- 지표 이름·정의·원본 값·단위·출처·표본 또는 운영 판단 근거·적용 범위·갱신 시각을 제공한다.
- 반영 방식·비중·점수 근거·미적용 이유는 지표값과 구분해 설명한다. 상세 설명은 결정된 모델과 일치해야 한다.
- 막대 길이는 표기된 지표 눈금의 값이다. 높을수록 좋은지 나쁜지, 개인 정보와 상호작용하는지도 설명한다.
- 승률·픽률·밴율, 운영 평가, API 숙련도는 단위가 다르다. 눈금 없는 막대로 서로 비교하게 하지 않는다.
- 숫자·텍스트·스크린리더 설명을 함께 제공한다. 모바일·키보드·터치에서 근거와 이의제기를 사용할 수 있게 한다.
- 개인 API 항목에는 새로고침, 직접 입력 항목에는 내 입력 수정을 제공한다.
- STATIC BLOOM의 인쇄 지면·강한 타이포그래피·형광펜 강조를 유지한다.

## 8. 기존 위키 연계 이의제기

- 공통 지표의 `이의제기`는 기존 **`티어표 건의` 일반 위키 문서**의 편집 흐름으로 연결한다. 별도 접수함은 만들지 않는다.
- 챔피언·포지션·지표 ID·현재 표시 값·데이터 버전·근거 화면 링크를 제안 문안에 채워 넣는다.
- 이용자는 수정 제안값(선택)·이유(필수)·참고 자료(선택)를 작성한다. 기존 본문은 유지하고 지표별 제안을 추가하는 흐름으로 설계한다.
- 로그인·편집·검토·리비전·제출 제한은 기존 위키 규칙을 그대로 따른다. 위키의 추가 편집이 즉시 반영돼도 원본 평가값은 바뀌지 않는다.
- 운영자는 위키에서 이의를 검토해 수정·유지·추가 자료 요청과 이유를 남긴다.
- 수정을 결정하면 운영자 메뉴에서 해당 지표를 변경하고 근거가 된 위키 리비전을 연결한다. 위키 승인만으로 자동 수정하지 않는다.
- 새 값·이전 값·적용 범위·수정자·시각·근거를 기록하고 새 지표 버전으로 게시한다.
- 의견과 처리 결과는 위키 역사로, 실제 수치 변경은 운영 지표 변경 기록으로 추적한다.
- API 키·선택 계정의 개인 데이터는 공개 제안에 자동 첨부하지 않는다.

## 9. 운영자 지표 관리 메뉴

- 기존 `/admin/tier-list`를 확장해 초기 **장인 의존도·선픽 적합도·조작 난이도**를 설정한다. 수동 등급 배정과 지표 설정을 구분한다.
- 포지션·챔피언으로 대상을 찾고 세 지표의 값·눈금 정의·근거·적용 패치를 입력·수정한다.
- 미입력은 미입력 상태로 두고 자동으로 0을 채우지 않는다. 지표 값의 허용 범위와 필수성은 해당 정의·모델에 따른다.
- 초기 게시 후에도 운영자가 값을 수정한다. 위키 이의제기에 따른 수정은 해당 리비전을 근거로 연결한다.
- 서버에서 관리자 권한·대상 챔피언·포지션·지표 범위와 값의 유효성을 검사한다.
- 게시할 값과 근거를 확인하고 변경 기록을 남긴다. 잘못된 변경은 이전 버전으로 복원할 수 있다.
- 현재 보드의 최종 수동 등급을 입력하는 기능만으로 이 요구를 충족한 것으로 간주하지 않는다.

## 10. 데이터 모델과 운영 전환

논리 모델이며 테이블 이름·마이그레이션은 구현 시 정한다.

| 데이터 | 필요한 값 |
| --- | --- |
| 평가 범위 | 서버·모드·패치·포지션·실력 구간·기간·갱신 시각 |
| 지표 정의 | ID·이름·단위·범위·의미·출처 유형·토글 가능 여부 |
| 챔피언 지표 스냅숏 | 값·출처·표본·운영 근거·수정자·버전·위키 리비전 연결 |
| 평가 모델 | 별도 모델 명세·버전·계수·등급 경계·결측/제외 규칙·게시 상태 |
| 개인 입력 | 선택 계정·현재 티어·챔피언별 숙련도·API/직접 입력 구분·조회/수정 시각 |
| 화면 설정 | 선택 포지션·일반/개인화·제외 지표 목록 |
| 이의제기 연결 | 기존 위키 문서/리비전·대상 지표/스냅숏·연결된 운영 변경 기록 |

- 데이터 스냅숏과 모델은 호환되는 버전으로 게시하고 같은 보드에 맞지 않는 버전을 섞지 않는다.
- 운영자는 공통 지표값과 근거를 관리한다. 새 방식의 최종 등급은 결정된 모델의 함수가 산출한다.
- `tier_placements`는 수동 등급만 저장하므로 새 산식의 원본이 될 수 없다. 준비 과정에서는 기존 보드를 유지하고 검증 후 전환한다.
- 복원할 때는 호환되는 스냅숏·모델 버전을 함께 복원한다. 개인 설정·챔피언 위키는 지우지 않는다.
- 이번 PRD 변경으로 D1·운영 위키·사이트 코드를 바꾸지 않는다. 기존 위키의 배정 방식 설명은 실제 기능 전환 시 갱신한다.

## 11. 단계별 개발 범위

| 단계 | 구현 | 완료 조건 |
| --- | --- | --- |
| 1. 지표와 운영 | 공급원·범위·스냅숏·운영자 지표 메뉴·변경 이력 | 실제 통계와 운영자가 입력한 세 지표를 근거·버전과 함께 조회 |
| 2. 모델과 일반 score | 별도 모델 논의·명세 확정 후 계산 함수·등급·일반 보드 | 합의한 모델로 재현 가능한 score·등급과 결측 상태를 제공 |
| 3. 개인화와 토글 | Riot API 현재 티어·숙련도·선택적 직접 입력·설정·제외 토글 | 자동 입력 우선, API 실패·부분 입력·설정 복원·일반 복귀 처리 |
| 4. 설명과 위키 연계 | 가중치 막대·모델 근거·위키 제안 연결·운영 수정 연결 | 표시 근거와 계산이 일치하고 이의제기와 실제 변경을 추적 |

모델이 아직 정해지지 않았어도 지표 정의·운영 메뉴·API 입력 조사 작업은 진행할 수 있다.
공개 점수는 모델과 실제 근거 데이터가 준비된 뒤 제공한다. 가짜 통계·예시 값을 제품 데이터로 채우지 않는다.

## 12. 수용 기준

- [ ] score를 특정 범위로 강제하지 않고 별도 모델 명세를 따른다. 유효 점수가 고정 0~100을 벗어나도 임의로 잘라내지 않는다.
- [ ] 같은 스냅숏·모델·개인 입력·토글에 같은 결과가 나오고 실제 모델의 등급 경계가 겹치지 않는다.
- [ ] Riot API로 현재 티어·챔피언 숙련도를 가져오면 같은 항목의 설문을 요구하지 않는다.
- [ ] 현재 티어는 대상 큐에서 선택하고 최고 티어를 수집·저장·계산하지 않는다.
- [ ] API 원본 숙련도와 직접 입력의 출처를 구분하고 모델에 따라 변환한다.
- [ ] 조회 실패·정상 빈 결과·명시적 0·미입력을 구분한다. 개인 정보가 없으면 일반 보드를 제공한다.
- [ ] 토글 OFF 항목과 의존 계산이 제외되고 점수·등급·정렬·설명이 함께 바뀐다. 기본 설정을 복원할 수 있다.
- [ ] 필수 자료가 부족하거나 적용할 지표가 없으면 score·등급을 만들어 내지 않는다.
- [ ] 운영자가 관리 메뉴에서 장인 의존도·선픽 적합도·조작 난이도를 설정·수정하고 비관리자의 쓰기는 서버에서 차단된다.
- [ ] 통계 출처·표본·범위·갱신 시각과 운영 평가의 값·근거·변경 기록을 확인할 수 있다.
- [ ] 지표 막대·숫자·단위·설명이 일치하며 모바일·키보드에서도 이용할 수 있다.
- [ ] 이의제기는 기존 위키로 연결되고 대상 지표·버전이 특정된다. 위키 편집만으로 원본 값이 바뀌지 않는다.
- [ ] 운영 지표 변경에 위키 근거 리비전이 연결되고 이전 버전 복원으로 결과를 재현할 수 있다.
- [ ] 개인 설정 수정·삭제·저장 실패와 API 새로고침을 처리하고 개인 데이터가 URL·공개 제안에 자동 노출되지 않는다.

사용자 유용성 평가는 일반→개인화 적용, API 성공·실패, 지표 설명 열람, 토글 사용·복원,
위키 이동·이의제기 처리 시간을 제안한다. 추적 도구·동의·목표 수치는 출시 전 결정한다.

## 13. 후속 결정할 사항

| 항목 | 결정이 필요한 내용 |
| --- | --- |
| 별도 평가 모델 | score의 범위·산식·계수·변환식·등급 경계·검증 방식 |
| 평가 대상 | 초기 서버·모드·일반 보드 실력 구간과 현재 티어 활용 |
| API 숙련도 활용 | 레벨·포인트·최근 플레이의 선택·변환과 기록 없음 처리 |

| 통계 공급원·표본 | 집계 규모·비용·최소 표본·최신성·필수 지표 |
